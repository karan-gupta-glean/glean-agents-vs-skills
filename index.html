Agents vs. Skills

A Guide for Glean Customers — understanding when to use each and how they work together

At a Glance

Skills are reusable instructions that the Glean Assistant and Agents can invoke to perform specific tasks.

Agents are purpose-built digital workers that package skills, tools, and knowledge with enterprise-grade governance, scoping, and operational controls for high-value production workflows.

Both are powerful on their own. Together, they let you automate anything from a simple formatting task to a fully governed, cross-system workflow.
🤖

What Makes Agents Unique

Capabilities that distinguish Agents from Skills — dedicated identity, external deployment, and constrained execution
1 Independent Identity agent-only
What Agents Enable
  • Execute with their own service account identity, separate from individual users
  • Access privileged tools and systems that no end-user should have direct access to
  • Run in the background without requiring a logged-in user
  • Produce audit trails that clearly distinguish Agent actions from human actions
Example
Employee asks: "Reset my password"
IT Agent → Executes using IT service account credentials
— the employee never has direct access to the password reset system
Audit log → Shows "IT Agent" performed the action, not the user
🤖 Agent
Executes with its own service account identity and privileged access
✨ Skill
Executes in the user's own security context — the right model for user-initiated tasks where standard permissions apply
2 Deployment to External Surfaces agent-only
What Agents Enable
  • Install where your teams already work — Slack channels, ServiceNow, Microsoft Teams
  • Respond 24/7 in dedicated channels without requiring users to open a separate app
  • Standalone presence in third-party systems
Example
✔ Your IT Agent lives in the #it-help Slack channel, responding to employee questions 24/7
✔ Your HR Agent is embedded in the ServiceNow portal
✔ Your Sales Agent is surfaced in Microsoft Teams
🤖 Agent
Extends Glean's reach into the platforms your teams already use daily
✨ Skill
Accessed through the Glean Assistant — the natural home for user-driven tasks and queries
3 Scoped & Constrained Execution agent-only
What Agents Enable
  • Run in a constrained environment with explicit boundaries on tools and knowledge sources
  • An IT Helpdesk Agent is scoped to IT documentation and ticketing systems only
  • Responses stay within domain at the architecture level
🤖 Agent
Constrains access at the system level — the agent architecturally cannot access out-of-scope data or tools
✨ Skill
Achieves scoping through model instruction following — the skill's prompt directs which knowledge and tools to use. Can also include code execution (Python via Agent Sandbox). Works well for the vast majority of use cases.
When to choose Agents over Skills for scoping: When workflows demand higher degrees of reliability — such as compliance-sensitive domains or regulated processes — Agents provide an additional layer of enforcement by constraining access at the system level rather than the prompt level.

Understanding Skills

The building blocks of AI automation in Glean — reusable, single-purpose capabilities

Skills are reusable, single-purpose capabilities that can be invoked by the Glean Assistant or by Agents. Any user can create a skill. What differentiates skills is how broadly they're shared and where they're used.

👤 Personal Use

A skill you create lives in your own library by default. You can use it in the Assistant and share it with specific colleagues.

👥 Team or Department-Wide

Departmental Skill Admins can share skills across their departments, standardizing workflows for entire teams.

🌎 Org-Wide

Org-wide Skill Admins can deploy skills to the entire organization, ensuring every user has access to approved, standardized capabilities (e.g., a Brand Voice skill or a MEDDPICC qualification skill).

🔒 Agent-Scoped

Skills can be built specifically for use within an Agent's domain, providing specialized capabilities that only that Agent invokes (e.g., a password reset workflow with MFA verification used only by the IT Agent).

Key principle: Skills are ingredients. Agents and the Assistant consume them. A well-designed skill library means every Agent and every user benefits from shared, tested capabilities.

Decision Framework

When to build an Agent vs. a Skill
Build This When You Need Key Characteristics
Agent Governance, scoped access, independent identity, or deployment to external surfaces Own service account, constrained tools/knowledge, versioning, observability, dedicated ownership
Skill A reusable capability for the Assistant or Agents to invoke Single-purpose, shareable at any scope (personal, team, org-wide), can be agent-scoped or broadly available

Practical Examples

Concrete scenarios showing when to choose an Agent vs. a Skill

Example 1: Weekly Reporting

✨ As a Skill: A "Weekly Report" skill drafts a document when a user asks for one — great for on-demand reporting.
🤖 As an Agent: A Weekly Report Agent runs every Friday on a schedule, automatically gathers metrics, drafts the report, and distributes it to stakeholders.
When to choose Agent: When the workflow requires independent scheduling, its own service account for data access, and lifecycle controls.

Example 2: Email Sending

🔒 As an Agent-Scoped Skill: Building send_email() inside the Sales Agent only.
🌎 As a Shared Skill: Making send_email() an org-wide skill so the Assistant, Sales Agent, IT Agent, and Marketing Agent can all use it.
When to share broadly: When a capability is horizontal — needed by many users and Agents across the organization.

Example 3: Password Reset

🌎 As a Broadly Shared Skill: Making the password reset workflow available as an org-wide capability.
🔒 As an Agent-Scoped Skill: Building it as a specialized skill scoped to the IT Agent, which has the privileged access and governance controls to handle it.
When to choose Agent-Scoped: When the operation involves approval workflows, MFA verification, or other domain-specific logic that belongs within a governed Agent context.

How Agents and Skills Work Together

Think of Skills as the tools in a toolbox, and Agents as the specialists who use those tools for specific jobs
  • Org-wide skills provide shared, standardized capabilities across the company: sending emails, searching knowledge bases, formatting JIRA tickets, enforcing brand guidelines.
  • Agents are deployed for specific domains: IT Helpdesk, HR Support, Sales Enablement. Each Agent uses a combination of shared skills and its own Agent-scoped skills.
  • The Glean Assistant serves as the general-purpose interface, using available skills to help users with everyday tasks that don't require a specialized Agent.
  • Personal and shared skills let individuals and teams customize their workflows — tailoring the Assistant to their specific work style, processes, and preferences.

Enterprise Governance & Controls

Consistent, unified governance model for both Agents and Skills

Glean provides enterprise-grade governance for both Agents and Skills using the same patterns for admin roles, tiered sharing, and per-item permissions.

Governance Capability Agents Skills
Admin roles Agent Moderator, Departmental Agent Moderator Org-wide Skill Admin, Departmental Skill Admin
Who can create Controlled via "Can create agents" toggle All users can create skills for themselves
Share with specific users/groups Gated by "Can share and publish" toggle Available to everyone
Share with departments Departmental Agent Moderator Departmental Skill Admin
Share org-wide Agent Moderator Org-wide Skill Admin
Per-item permissions Viewer, Editor, Owner Viewer, Editor, Owner
Admin override Admins have Owner-level access to all agents Admins have Owner-level access to skills they create and control who shares skills org-wide or to departments
How It Works in Practice
Admin Roles

Both use a tiered admin model. For Agents, the Agent Moderator can create, edit, delete, view, or share anyone's agent across the organization, while the Departmental Agent Moderator has the same capabilities scoped to their departments. Skills follow the same pattern with Org-wide Skill Admin and Departmental Skill Admin roles.

Sharing Scope

Both Agents and Skills tie sharing scope to admin roles, so organizations can democratize creation while controlling distribution. Any user can share with specific colleagues, but sharing to departments or the entire organization requires the appropriate admin role.

Super Admins and Admins receive full governance capabilities by default for both Agents and Skills, consistent across the platform.

Getting Started

A practical path to deploying Agents and Skills in your organization
  1. 1 Identify high-value workflows that would benefit from dedicated Agents — IT helpdesk, HR support, and sales enablement are common starting points.
  2. 2 Audit existing capabilities to determine which can be built as reusable shared skills versus Agent-scoped capabilities.
  3. 3 Start with a pilot Agent in a well-defined domain with clear success metrics (e.g., IT ticket resolution rate, average response time).
  4. 4 Expand your skill library as you deploy more Agents, ensuring reusable skills are built once and shared across the organization.
