Customer Guide

Agents vs. Skills

Understanding when to use each and how they work together to automate work across your organization.

🤖

Agents

Purpose-built digital workers that package skills, tools, and knowledge with enterprise-grade governance, scoping, and operational controls for high-value production workflows.

✨

Skills

Reusable instructions that the Glean Assistant and Agents can invoke to perform specific tasks. The building blocks of AI automation.

Core Capabilities

What Makes Agents Unique

Agents are designed for workflows that require dedicated identity, external deployment, or constrained execution environments.

1

Independent Identity

Agents execute with their own service account identity, separate from individual users.

  • Access privileged tools and systems that no end-user should have direct access to
  • Run in the background without requiring a logged-in user
  • Produce audit trails that clearly distinguish Agent actions from human actions
Example: An employee asks the IT Agent to reset their password. The Agent executes using IT service account credentials — the employee never has direct access to the password reset system, and the audit log shows "IT Agent" performed the action.
🤖 Agent
Own service account identity and privileged access
✨ Skill
Executes in user's security context with their standard permissions
2

Deployment to External Surfaces

Agents can be installed where your teams already work.

  • Deploy to Slack channels, ServiceNow, Microsoft Teams
  • Respond 24/7 without requiring users to switch apps
  • Standalone presence in third-party systems
Example: Your IT Agent lives in the #it-help Slack channel, responding to employee questions 24/7. Skills are accessed through the Glean Assistant, which is the natural home for user-driven tasks.
🤖 Agent
Extends Glean into the platforms your teams already use daily
✨ Skill
Accessed through the Glean Assistant — the natural home for user-driven tasks
3

Scoped & Constrained Execution

Agents run in a constrained environment with explicit boundaries.

  • Explicit boundaries on which tools they can access and which knowledge sources they can search
  • An IT Helpdesk Agent is scoped to IT documentation and ticketing only
  • Responses stay within domain at the architecture level
Skills achieve scoping through model instruction following and can include code execution via Agent Sandbox. When workflows demand higher reliability — such as compliance-sensitive domains — Agents provide system-level enforcement rather than prompt-level.
🤖 Agent
Access constrained at the system level — architecturally cannot break scope
✨ Skill
Scoping via prompt instructions — works well for the vast majority of use cases

Building Blocks

Understanding Skills

Skills are reusable, single-purpose capabilities that can be invoked by the Glean Assistant or by Agents.

Any user can create a skill. What differentiates skills is how broadly they're shared and where they're used.

👤

Personal Use

A skill you create lives in your own library by default. Use it in the Assistant and share with specific colleagues.

👥

Team / Department

Departmental Skill Admins can share skills across their departments, standardizing workflows for entire teams.

🌎

Org-Wide

Org-wide Skill Admins deploy skills to the entire organization — like a Brand Voice skill or MEDDPICC qualification skill.

🔒

Agent-Scoped

Skills built for use within a specific Agent's domain — like a password reset workflow only the IT Agent invokes.

Key principle: Skills are ingredients. Agents and the Assistant consume them. A well-designed skill library means every Agent and every user benefits from shared, tested capabilities.
Decision Guide

When to Build What

A simple framework for choosing between Agents and Skills.

Build This When You Need Key Characteristics
Agent Governance, scoped access, independent identity, or deployment to external surfaces Own service account, constrained tools/knowledge, versioning, observability, dedicated ownership
Skill A reusable capability for the Assistant or Agents to invoke Single-purpose, shareable at any scope (personal, team, org-wide), can be agent-scoped or broadly available
In Practice

Practical Examples

Concrete scenarios showing when to choose an Agent, a shared Skill, or an Agent-scoped Skill.

Weekly Reporting

✨ As a Skill Drafts a document when a user asks for one — great for on-demand reporting.
🤖 As an Agent Runs every Friday on a schedule, gathers metrics, drafts the report, and distributes it to stakeholders.
Choose Agent when the workflow requires independent scheduling, its own service account for data access, and lifecycle controls.

Email Sending

🔒 Agent-Scoped Skill Building send_email() inside the Sales Agent only.
🌎 Shared Skill Making send_email() org-wide so the Assistant, Sales, IT, and Marketing Agents can all use it.
Share broadly when a capability is horizontal — needed by many users and Agents across the organization.

Password Reset

🌎 Broadly Shared Skill Making the password reset workflow available as an org-wide capability.
🔒 Agent-Scoped Skill Built as a specialized skill inside the IT Agent with privileged access and governance controls.
Choose Agent-Scoped when the operation involves approval workflows, MFA verification, or domain-specific logic.
Better Together

How Agents and Skills Work Together

Think of Skills as the tools in a toolbox, and Agents as the specialists who use those tools for specific jobs.

🌎 Org-Wide Skills

Provide shared, standardized capabilities across the company: sending emails, searching knowledge bases, formatting JIRA tickets, enforcing brand guidelines.

🤖 Domain Agents

Deployed for specific domains — IT Helpdesk, HR Support, Sales Enablement. Each uses a combination of shared skills and its own Agent-scoped skills.

💬 Glean Assistant

The general-purpose interface, using available skills to help users with everyday tasks that don't require a specialized Agent.

👤 Personal Skills

Let individuals and teams customize their workflows — tailoring the Assistant to their specific work style, processes, and preferences.

Enterprise Controls

Enterprise Governance & Controls

Glean provides a consistent, unified governance model for both Agents and Skills using the same patterns for admin roles, tiered sharing, and per-item permissions.

Governance Capability Agents Skills
Admin Roles Agent Moderator, Departmental Agent Moderator Org-wide Skill Admin, Departmental Skill Admin
Who Can Create Controlled via "Can create agents" toggle All users can create skills for themselves
Share with Users/Groups Gated by "Can share and publish" toggle Available to everyone
Share with Departments Departmental Agent Moderator Departmental Skill Admin
Share Org-Wide Agent Moderator Org-wide Skill Admin
Per-Item Permissions Viewer, Editor, Owner Viewer, Editor, Owner
Admin Override Admins have Owner-level access to all agents Admins have Owner-level access to skills they create and control org-wide sharing

How It Works in Practice

Admin Roles

Both use a tiered admin model. For Agents, the Agent Moderator can create, edit, delete, view, or share anyone's agent across the organization, while the Departmental Agent Moderator has the same capabilities scoped to their departments. Skills follow the same pattern with Org-wide Skill Admin and Departmental Skill Admin roles.

Sharing Scope

Both Agents and Skills tie sharing scope to admin roles, so organizations can democratize creation while controlling distribution. Any user can share with specific colleagues, but sharing to departments or the entire organization requires the appropriate admin role.

Super Admins and Admins receive full governance capabilities by default for both Agents and Skills, consistent across the platform.
